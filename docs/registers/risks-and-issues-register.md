# Risks and Issues Register

Live register. Likelihood/impact: Low / Medium / High. All entries opened 2026-07-30.

## Risks

| ID | Risk | L | I | Mitigation | Status |
|---|---|---|---|---|---|
| R-001 | `@hey-api/openapi-ts` is pre-1.0 (0.99.0); breaking generator changes could invalidate the committed client or wrapper script | M | M | Exact pin; project-owned wrapper script; committed output; drift CI; upgrade only as a reviewed act (ADR-0005) | Open |
| R-002 | NativeWind 4.2 `rtl:`/`ltr:` variants are broken on native — a core hazard for an Arabic-first product | H | M | Use logical utilities (`ps-`/`pe-`, `start-`/`end-`) exclusively; forbid `rtl:`/`ltr:` variants via lint; RTL visual tests; NativeWind remains provisional until the en/ar × web/native × light/dark spike passes (Plan §19) | Open |
| R-003 | Two-runner test split (Vitest for TS packages, Jest Expo + RNTL for RN rendering) doubles config surface and can drift | M | L | Shared test utilities in `packages/testing`; both runners wired into one Turborepo pipeline and CI | Open |
| R-004 | TypeScript 7 ecosystem lag: staying on TS 6 while the ecosystem migrates could strand tooling | L | M | Recorded review trigger in ADR-0009 (typescript-eslint support + stable programmatic API); compatibility matrix tracks it | Open |
| R-005 | Windows host PHP lacks `pdo_sqlite` and `intl`; bare-host workflows may silently diverge from Docker/CI | M | L | PostgreSQL is the only test database; Docker image includes `intl`; document bare-host limits (A-005) | Open |
| R-006 | Garage v2 is a less common dev object store; behavioural gaps versus production S3 providers possible | L | L | Laravel filesystem abstraction only, no Garage-specific APIs (ADR-0010); validate against real provider before storing sensitive documents | Open |
| R-007 | Audit-log growth without partitioning degrades queries and complicates retention enforcement | M | M | Deliberate deferral (D-025) with review at first production tenant; append-only design keeps later partitioning tractable; retention decision pending (OQ-002) | Open |
| R-008 | Expo native layout-direction change requires an application reload; a poor flow would break the Arabic/English switch experience | M | M | Implement the explicit user-facing reload flow required by Plan §20; cover in RTL visual tests | Open |
| R-009 | Removing the starter kit's Teams feature and Inertia assets could break Fortify auth flows or leave dead schema | M | M | Plan §5 sequencing: identify auth behaviour/dependencies before removal; keep one canonical users migration; Pest coverage of auth before surgery | Open |
| R-010 | InterNACHI Modular spike could fail against Laravel 13 (discovery, config caching, Larastan, optimisation) | L | M | Gated spike before adoption (Plan §6); fallback to project-owned `app/Modules/` namespaces costs little | Open |
| R-011 | RLS session-variable context could interact badly with connection pooling/queue workers (stale tenant context) | M | H | Mandated verification tests: context reset on reused connections, queue-job context restoration, fail-closed on no context (ADR-0007) | Open |
| R-012 | Regulatory obligations in nine launch markets are unassessed; some may impose residency, licensing or health-data rules affecting architecture | M | H | Per-country assessment before real-tenant onboarding (OQ-003); no compliance claims made until assessed | Open |
| R-013 | SMS deliverability sits on the critical path of every transactional journey the source specifies — onboarding, guest ordering, closure, B2B signing — yet no provider is chosen and no delivery rate is measured in any launch market | H | H | Phone verification is configurable and **off in production** until a provider is approved; email-only activation is the production path; channel drivers are interfaces with log/fake implementations outside production; WhatsApp is a second channel (INT-006). Gate: A-011, OQ-008, INT-005 | Open |
| R-014 | KYC and B2B documents are accepted, stored and served back without malware scanning; a hostile upload reaches a reviewer's machine | M | H | Private disk, magic-byte sniffing, size cap, sha256, audited temporary-URL downloads and `purge_after` from B1 — but scanning is a **gate before real onboarding**, not an optimisation (INT-008, OQ-035) | Open |
| R-015 | Click-wrap acceptance of the B2B master service agreement may not be enforceable in every launch market, and could be mistaken internally for a qualified electronic signature | M | M | Evidence is recorded honestly (OTP challenge id, document sha256, consent grant, hashed IP and user agent) and **never described as a qualified e-signature** anywhere in copy, wire contract or audit vocabulary; qualified e-sign is a separate integration (INT-007) pending legal review | Open |
| R-016 | `users.email` and the future `contact_points` rows can drift: two stores of the same address, with verification state on one and authentication on the other | M | H | One canonical identity (D-045): a single write path mirrors the login email into contact points, a Verified listener keeps the states aligned, and a drift test fails the build if they diverge | Open |
| R-017 | `ConsentLedger::pendingFor()` returns every published definition regardless of audience, so seeding a definition aimed at one audience would raise a pending consent for everybody — including callers who can never satisfy it | M | H | Audience and `is_required` columns plus audience filtering are scheduled in J1. **Until that lands, no new consent definition may be seeded** — recorded here so the constraint is visible outside the phase that fixes it | Open |
| R-018 | Audit metadata redaction matches `REDACTED_KEYS` as a substring, so benign keys such as `country_code`, `allergen_code` or `error_code` are silently redacted, making audit rows less useful exactly where catalogue and allergen vocabulary is densest | M | M | Naming convention avoids the affected substrings until the matcher is fixed; fix is a matcher change plus a test, scheduled before the K1.8 catalogue audit vocabulary (OQ-036) | Open |
| R-019 | The source data contradicts itself on allergens: burghul and pita are tagged allergen-None against the file's own key, which for a gluten-bearing ingredient is a food-safety error, and importing it verbatim would publish a false allergen statement | H | H | The importer quarantines the affected ingredients as `review_required` (D-042), the allergen-review report escalates the contradiction to the product owner, and quarantined records are structurally unpublishable. **Not a data-cleanup task — a food-safety escalation.** K1.8 update: the first real import ran and the escalation fired — `Burghul (Bulgur)` and `Pita bread` are named at the top of the run's allergen-review section, and the same section lists **73 further ingredients** used by imported technical sheets that carry no allergen mapping in any layer, because the sheets record none (OQ-042). Every imported version is refused publication by the allergen gate until a human determines them | Open — escalated to the product owner |
| R-020 | Confidential GreenLife technical sheets, formulations and unit costs leak into the repository, a public projection or a tenant that should not see them | M | H | Four layers: the private importer keeps source data out of the repository entirely (D-046), PublicProjection presenters with a denylist (D-043), organisation RLS on recipe and cost tables, and automated literal sweeps that fail the build if a seeded distinctive cost literal appears on any anonymous surface | Open |
| R-021 | The programme adds endpoints faster than the OpenAPI document can be kept honest, and the committed contract drifts from the implementation | M | M | Spec-first is unchanged (ADR-0005): the document is edited before the controller, the bundle is committed, `gen:api` is drift-checked, and the route-to-spec parity test fails the build on any endpoint the document does not describe. Each phase stages its own additions (D-052) | Open |
| R-022 | Operator edits to seeded catalogue data are clobbered by a later import or reseed, silently reverting a kitchen's own corrections | M | M | The importer is insert-if-absent and idempotent: an existing record is never overwritten, the run reports created/skipped/failed counts, and the acceptance path proves an operator edit survives a re-run (D-046). K1.8 update: proven twice — a test edits a recipe line, a price and an ingredient name through the models and re-imports, and all three survive; and the real re-run against the live workbook created **nothing** and skipped every one of the 1 500-odd rows the first run wrote | Mitigated — control in place and exercised |
| R-023 | The curated designation dictionary is hand-written, so a typo in it fails silently: an alias pointing at an ingredient nothing creates simply stops resolving, and the run reports an unresolved designation as though the workbook were at fault | M | M | K1.8. The file is tested like code (`DesignationDictionaryTest`): every alias must land on a name that will exist, every category code must be in the platform taxonomy, every unit must be one the platform knows, slugs and names must be distinct, and the sets a curator refused to merge must still be apart. The importer never adds to the file, and there is no fuzzy matching anywhere in the import path (D-055) | Mitigated |
