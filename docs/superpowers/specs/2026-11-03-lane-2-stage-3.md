# Lane 2: P0 Stage 3, money and stock an owner can trust

Date: 3 November 2026. Built overnight on `P0-Stage1`. Tests written, none run.

## What was built

**Refunds and voids.** `order_refunds`, a ledger beside the receipts, with an order panel for managers. Full or partial, reason required, within 7 days, capped at the receipts. Above `refund_approval_above_minor`, default $50 and editable on the branch operating page, an entry waits for the owner, who hears through a new `refund_approval` bell alert. New permission `order.approve_refund_organisation`.

**Settlement.** `cash_settlements`, and `/kitchen/order-desk/settlement`. Per-shift driver hand-in with a short amount, reason and manager sign-off. Courier batches write each order's receipt. New permission `order.settle_cash_organisation`. The cash report now lists what came off the takings beside its rows.

**Stock accountability.** `stock_movements.actor_user_id`, stamped in `InventoryService`'s one write path. Adjustments and waste need a reason. Waste is valued at the moving average. A read-only page, `/kitchen/activity`, shows the ledger and the audit trail under `audit.view_organisation`.

**Subscription credit.** Removed everywhere. Cancelling writes no memo and works out no figure.

**No tax.** Receipts made no claim and there is no customer invoice. Two unused price hints said "incl. VAT" and "excl. VAT", so they were deleted.

## Decisions

1. **A new ledger, not the `refunds` table.** That table needs a `payment_intent_id`, and desk and delivery orders have receipts and no intent. `PaymentService::refund()` is unchanged and its locking rule was copied.
2. **Append-only by trigger.** Approval has to move a pending row once, so the `stock_movements` revoke would not fit. A trigger allows that one update and refuses every other update and every delete.
3. **Two kinds on one ledger.** A `refund` leaves the order paid, or staff would be asked to collect it again. A `receipt_correction` takes the money off `Order::receivedMinor()`, so the balance returns as outstanding. Both count against the same cap.
4. **The limit is cumulative per order**, so several small refunds cannot walk past it.
5. **Seven days run from the latest receipt**, so a deposit cannot close the window before the food arrives. Applied when an entry is requested, not when the owner answers.
6. **The owner alone approves.** The administrator does not hold the code. An owner's own refund completes at once.
7. **Refunds do not reduce order totals or revenue.** See "Skipped".
8. **The shift is whatever was not yet handed in.** There is no shift table and one was not added. `delivery_jobs.cash_settlement_id` records the coverage, which keeps receipts unedited and stops a run being settled twice.
9. **One table for drivers and couriers**, because a hand-in has the same shape either way.
10. **A courier's receipt is the order's full balance.** The customer paid in full, and a net receipt would leave every courier order owing the fee forever. The fee sits on the settlement and appears in the cash report.
11. **Handing in more than was due is refused**, for drivers and couriers. The ruling only covers short.
12. **Cashiers record; a short hand-in waits for `order.supervise_organisation`.** `branch_manager` holds the new code because Lane 3 gave that role the desk.
13. **Adjustments held no human reason**, so `notes` became required on adjustments and waste. A count with none is stored as "Stock count".
14. **A null actor reads "Unattributed".** That covers old rows and movements a job made with nobody signed in.
15. **A wasted late cancel now counts as waste in the monthly report.** Cancelled orders drop out of COGS, so its cost was counted nowhere.
16. **Unvalued waste is counted, not zeroed**, and the Activity page says how many entries had no cost held.
17. **Credit memos already on file stay.** The account-closure check still reads them. `credit_memos` gains no rows.

## Skipped, and when to add it

- **Refunds in revenue and margin.** The monthly report and analytics still read order totals. Add when Stage 2's truthful margin work settles what revenue means.
- **Bell alerts for a short hand-in, and for the requester when the owner decides.** Both show on their pages. `StaffAlerts` links only to orders today.
- **A history cut-off for settlement.** Runs delivered before this shipped count as unsettled, so the first hand-in may be long. It clears once.
- **A waste reason list.** The reason is free text. Add a fixed list if the owner wants waste broken down by cause.
- **Order links on the Activity page.** It prints the order number.
- **Sending money.** Nothing here pays anyone. It records what staff did by hand.
