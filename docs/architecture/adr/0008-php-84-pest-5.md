# ADR-0008 — PHP 8.4 with Pest 5

## Status

Accepted — 2026-07-30.

## Context

The adopted Laravel 13.23 application was generated with Pest 5, and Pest 5 (with `pest-plugin-laravel` 5.0.x) requires PHP `^8.4`. The project mandate requires "PHP 8.3 or later". The development host runs PHP 8.4.11 (with `pdo_pgsql` and `redis`; notably lacking `pdo_sqlite` and `intl` — recorded in the risks register).

## Decision

Standardise on PHP 8.4 across local development, Docker (PHP 8.4 FPM) and CI. Keep Pest 5 as the test framework with Larastan 3 (PHPStan 2.2) and Pint for static analysis and formatting. The "PHP 8.3 or later" mandate is satisfied by 8.4; we do not maintain 8.3 compatibility.

## Consequences

- No dual-version support burden; language features up to 8.4 (property hooks, asymmetric visibility) are usable.
- Any environment that can only offer PHP 8.3 cannot run the test suite (Pest 5 hard-requires 8.4) — hosting choices must guarantee 8.4.
- The host's missing `pdo_sqlite` means SQLite-based test shortcuts are unavailable; tests run against PostgreSQL, which is truer to production anyway. Missing `intl` must be compensated by the Docker image (which includes it) or by avoiding intl-dependent code paths on the bare host.

## Review trigger

Re-examine at PHP 8.5/Laravel 14 releases, or if a mandated deployment target cannot provide PHP 8.4.
